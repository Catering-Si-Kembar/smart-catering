## 1. Ringkasan Eksekutif

Catering Si Kembar saat ini masih menghitung kebutuhan bahan baku secara manual, mencatat keuangan di buku fisik, dan memantau jadwal pesanan di Google Spreadsheet yang terpisah. Akibatnya invoice terbit beberapa jam hingga keesokan hari, respons WhatsApp terasa lambat, dan karyawan, terutama yang kurang terbiasa dengan teknologi, harus berulang kali bertanya kepada pengelola.

Tim membangun prototype/MVP web manajemen katering bagi pengelola dan staf. Alur utama mencakup input pesanan, perhitungan bahan dari resep standar, invoice digital, DP dan pelunasan, serta dasbor jadwal. Fitur tambahan meliputi chatbot Agentic RAG berbasis API LLM dan tool calling, forecasting, sentimen, dasbor analitik, reminder WAHA/email, serta AI Business Insight dengan unduhan PDF. RAG memakai model embedding dan ChromaDB. Insight dibuat SLM/LLM open-source. Arsitektur memakai frontend Next.js di Vercel, backend Express terpisah, FastAPI, PostgreSQL, ChromaDB, dan worker VPS. Model embedding diuji sebelum deployment, sedangkan inference SLM disiapkan terpisah. Fitur tambahan tidak boleh menunda alur utama yang ditargetkan selesai akhir minggu ketiga.

Tim menguji secara internal sejak fitur dibuat. Pada minggu keempat, PIC mencoba skenario input 100 nasi box dan memberi feedback. Data berasal dari menu, bahan baku, resep, dan rekap pesanan yang dikonfirmasi UMKM, atau data sintetis berlabel yang disetujui PIC. Hasil kerja berupa aplikasi web publik, kode sumber, README, user manual, dan catatan pengujian. Hasil capstone adalah prototype untuk demonstrasi dan validasi. Dampak bisnis tidak diklaim telah tercapai dan UMKM tidak wajib mengadopsi solusi ini.

### Yang tidak dikerjakan

- Integrasi payment gateway dan verifikasi pembayaran otomatis.
- Integrasi Shopee atau marketplace eksternal lainnya.

- Sistem inventaris dan pengelolaan stok bahan baku secara real-time.

- Forecasting tingkat lanjut untuk operasional nyata dengan jaminan akurasi prediksi.

- Pengambilan keputusan bisnis otomatis oleh AI tanpa validasi pengguna.
- Penggunaan aplikasi sebagai sistem produksi komersial penuh.

### Alur kerja aplikasi

Alur kerja aplikasi berjalan sebagai berikut.

- Pengguna membuka frontend Next.js di browser desktop atau ponsel. Axios mengirim request REST /api/v1 ke backend Express terpisah.
- Backend Express memvalidasi data dengan Joi, memproses bahan baku, invoice, pembayaran, menyimpan ke PostgreSQL melalui Prisma, lalu mengirim JSON ke dasbor.
- Untuk chatbot, frontend mengakses Express lalu FastAPI. Model relevansi dua kelas menyaring pertanyaan di luar konteks, sedangkan API LLM memilih tools RAG atau database sesuai kebutuhan dan hak akses. Kegagalan ditangani dengan jelas.
- Informasi menu, FAQ, dan SOP dicari melalui embedding dan ChromaDB, lalu dijawab API LLM. Data pesanan dan pembayaran diambil melalui backend tools baca-saja sesuai hak akses.
- API LLM menjawab RAG. SLM membuat insight laporan. Backend membuat PDF dan menyimpan riwayat chat.
- Untuk prediksi, backend memanggil layanan forecasting. Hasilnya digabung dengan resep terkonfirmasi untuk menampilkan estimasi kebutuhan bahan.
- Cron sistem pada VPS memicu worker Node.js untuk membaca jadwal reminder, mengirim notifikasi melalui in-app, WAHA, atau email opsional, serta mencatat status pengiriman agar tidak terjadi duplikasi.
- API key hanya disimpan di server.
